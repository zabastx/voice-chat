# Прототип Windows-клиента на Tauri 2

Проверяем, сколько памяти потребляет существующий интерфейс в WebView2. Ориентир:
100–200 МиБ на всё дерево процессов во время голосового звонка в трее без видео.
Это эксперимент в ветке `prototype/tauri-windows`, не готовый релиз клиента.

Первый завершённый замер: **239,5 МиБ в звонке в трее с двумя участниками**.
Цель пока не достигнута. Подробности и ограничения измерения находятся в
[матрице проверок](../docs/progress/verification.md#v0250--tauri-2-windows-prototype).

Клиент открывает серверное приложение. Nuxt, Postgres и LiveKit остаются на сервере.
Используются обычная авторизация сайта и отдельный профиль WebView2, поэтому в клиент
нужно войти отдельно. Профиль сохраняется между запусками. Сервер должен быть доступен.

## Запуск

Для сборки нужны Windows, [Rust MSVC, C++ Build Tools и WebView2](https://v2.tauri.app/start/prerequisites/).
Команды выполняются из корня репозитория:

```powershell
bun install
bun run desktop:build
# Сервер по умолчанию: http://localhost:3000. В другом терминале: bun run dev
bun run desktop:run
```

Для уже работающего сервера:

```powershell
$env:VOICECHAT_DESKTOP_URL = 'https://chat.example.com'
bun run desktop:run
```

Для пересборки при изменениях Rust: `bun run desktop:dev`. Скрипт использует установленный
Rust или локальную установку в `.data/tooling/{cargo,rustup}`, если она есть.
Режим `desktop:dev` не запускает Nuxt автоматически.

Результат release-сборки:
`src-tauri/target/release/voice-chat-desktop-prototype.exe`. Это переносимый EXE без
установщика и автообновлений, которому нужен установленный WebView2. При прямом запуске
EXE также учитывает `VOICECHAT_DESKTOP_URL`; без неё подключается к localhost:3000.

Крестик скрывает окно в трей, сохраняя страницу и звонок. Левый клик по иконке открывает
окно. Правый клик открывает меню «Открыть чат», «Свернуть в трей», «Выйти из приложения».
Повторный запуск показывает уже открытый экземпляр. Ссылки в новом окне открываются
в обычном браузере. Страница не получает разрешений на вызов команд Tauri.

`bun run desktop:run --tray` запускает клиент в трее или скрывает уже открытое окно.
Обычный `bun run desktop:run` возвращает его на экран.

## Замер памяти

Используйте release EXE и production-сборку сервера (`bun run build`, затем `bun run preview`).
Dev-сборка Nuxt добавляет HMR и искажает сравнение. После входа и подключения к каналу
дайте приложению стабилизироваться, затем выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File desktop-prototype/measure.ps1 -Label call-tray
```

Скрипт находит единственный запущенный прототип и всех его потомков, включая WebView2,
GPU и аудиосервисы. Он сохраняет три снимка и медиану в `.data/desktop-memory/<Label>.json`.
`privateMiB` соответствует private commit из [бенчмарка браузера](../docs/BENCH.md).
`workingSetMiB` приведён отдельно; он включает общие страницы, поэтому суммы нельзя
трактовать как уникальную физическую память. Данные профиля и результаты замеров не
коммитятся. Отладочный CDP-порт при обычном запуске не включён.

Сравнивать нужно одинаковые данные, размер окна, состав звонка и время ожидания.
Отдельно измеряйте открытый чат, трей без звонка, звонок и звонок в трее.
Уменьшение памяти и попадание в бюджет подтверждаются только результатами замеров.

`bun run desktop:bench` выполняет локальный эксперимент автоматически: входит тестовыми
учётными записями `danil` и `maks`, соединяет Tauri и Chrome в `bench-voice`, проверяет
двусторонние RTP-счётчики, скрытие в трей и восстановление. Требуются production-сервер
на localhost:3000, установленный Chrome и канал из `bun run bench:seed`. Закройте обычный
клиент перед запуском. Вместо микрофона генерируется синтетический тон, воспроизведение
выключено. CDP-порт 9337 включается только на время эксперимента; результаты и скриншот
попадают в `.data/desktop-memory`. Это проверка передачи аудио, не качества реального звука.

Короткая проверка трея без звонка: `node desktop-prototype/tray-check.mjs`.
У single-instance есть служебное окно с суффиксом `-siw`, поэтому скрытый клиент всё ещё
имеет ненулевой `MainWindowHandle`. Скрипт отличает его от окна чата. В этом эксперименте
`document.visibilityState` оставался `visible` даже при скрытом Windows-окне.

## Границы эксперимента

Push-to-talk ещё не реализован. Для него нужен отдельный проход с проверкой нажатия и
отпускания клавиши в фоне и при игре. Захват экрана со звуком, выбор устройств,
«Смотреть вместе», сон/пробуждение и длительные звонки требуют проверки в WebView2.
Скрытие окна сохраняет WebView целиком; голос пока не отделён от интерфейса.

API, использованные в оболочке: [окна](https://docs.rs/tauri/latest/tauri/webview/struct.WebviewWindowBuilder.html),
[трей](https://v2.tauri.app/learn/system-tray/), [разрешения](https://v2.tauri.app/security/capabilities/).
