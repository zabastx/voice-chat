| Crawler / AI-scraper blocking (search engines + LLM training)    | ✅ done     | Four layers, since no single one binds every actor: [robots.txt](../../public/robots.txt) is now `Disallow: /` (it previously allowed everything — an empty `Disallow:` means "allow all") plus ~40 named AI/SEO crawlers, because opt-out tokens like `Google-Extended` and `Applebot-Extended` are only honoured when named and never inherit the `*` group; an `X-Robots-Tag` route rule in [nuxt.config.ts](../../nuxt.config.ts) covering `/**` (API + assets included) for bots that fetch first and read directives later; `<meta name="robots">` in [app.vue](../../app/app.vue); and a `header_regexp` matcher in [deploy/Caddyfile](../../deploy/Caddyfile) that answers named crawler UAs with a bare 403 so the app is never reached. `/robots.txt` is deliberately exempt from the 403 — a 4xx on robots.txt is specified to mean "no restrictions", i.e. the opposite of the intent. Only explicit crawler UAs are matched; generic clients (browsers, `curl`, the Telegram/LiveKit machinery) must keep working, so no `python-requests`/`Go-http-client`-style patterns                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

| Watch Together (YouTube video/Shorts/live in a voice channel)    | ✅ built    | v0.18.0, [ADR 0008](../adr/0008-watch-together-synced-embeds.md) (synced embeds, never the SFU) + [ADR 0009](../adr/0009-watch-session-in-memory-anyone-controls.md) (ephemeral state, anyone controls). Server: in-memory `Map` in [watch-state.ts](../../server/utils/watch-state.ts) beside `voice-state.ts`, anchor **resolved at send time** so no client ever compares clocks; `POST/DELETE /api/channels/:id/watch`, `.../watch/state`, `.../watch/meta`, each gated by [watch-guard.ts](../../server/utils/watch-guard.ts) which resolves the room from `voiceChannelOf(caller)` rather than the `:id` sent. State out as a **parallel** `watch` map in the WS `snapshot` + a `watch.state` event — `VoiceRooms` untouched. Client: [useWatch.ts](../../app/composables/useWatch.ts) owns the anchor (re-anchored on `performance.now()`) + commands + actor toasts; the player is mounted **once in the layout** ([WatchPlayerHost.vue](../../app/components/WatchPlayerHost.vue), outside `<NuxtPage>`) so navigating to a text channel doesn't stop it — it docks over a placeholder `ChannelVoice` registers ([useWatchStage.ts](../../app/composables/useWatchStage.ts), rAF-tracked) or becomes a draggable 320x180 mini player, with no close button since the Audience is the roster; [WatchStage.vue](../../app/components/WatchStage.vue) owns the YT IFrame player, 3s drift loop (hard seek past 2s), `applyingRemote` echo guard + threshold backstop, and the «Нажмите, чтобы смотреть» autoplay fallback. The iframe host node is created **imperatively** so Vue never owns the element the YT API replaces, and `WatchStage` is rendered in exactly one place in `ChannelVoice.vue` (tile focus is disabled while watching) — reparenting an iframe restarts the video. Live broadcasts sync play/pause only, detected client-side via the undocumented `getVideoData().isLive` — reported as **positives only**, and latched on server-side, because "not live" is indistinguishable from "not loaded yet". Drift is corrected locally and never broadcast; a seek is distinguished from drift by comparing playhead advance against elapsed wall time, since with native controls the two are otherwise the same observation. Deliberate no-s: no queue, no host, no auto-ducking, no Twitch yet, no DRM sources. Gates green; parser exercised against 23 cases via a throwaway script (this repo has no test runner, so nothing is committed) — **needs headed two-browser verify**. Hardened after an adversarial review that found 14 real defects in the first cut, incl. late joiners silently desyncing, one viewer's ad rewinding the room, and live streams being seeked to the start of the DVR window; see [gotchas 18b–18f](../GOTCHAS.md) |
