| Persistent Sign-ins («запомнить меня») + Sign-in Epoch revocation         | ✅ built    | v0.23.0, [ADR 0012](../adr/0012-sign-in-epoch-revocable-sessions.md). Before this, nothing set `session.maxAge`, so every Sign-in was a browser-session cookie that died on close (Chrome's session restore masked it). Now: a rolling 400-day cookie expiry written by `issueSignIn` itself (the Chrome/Safari `Max-Age` clamp — the honest ceiling), a «Запомнить меня» checkbox on the login form **ticked by default**, and rolling renewal past 7 days so an active member is never logged out. Persistence shipped together with revocation because it had to: `members.sign_in_epoch` is stamped into the cookie and compared in [session-member.ts](../../server/middleware/session-member.ts) — which already read the member row per authed `/api/**` request, so the check costs one extra column, not an extra query. Bumped by own password change, admin password reset, and `POST /api/me/sign-out-all` (Настройки → Профиль, logs out the current device too) / `POST /api/members/:id/sign-out-all` (admin cutoff in ManageModal); each bump also calls `wsDisconnectMember`, since a WS is authed only at connect and a revoked device would otherwise keep receiving messages live. Deleting a member needs no bump — the existing member-missing branch covers it. Role changes deliberately do **not** bump (adr/0002 already handles them; logging out a demoted moderator mid-conversation is louder than the change warrants). `/api/auth/*` is skipped by the middleware, so `refresh.post.ts` carries its own epoch check or it would re-seal a revoked cookie back to life. Opt-out branch = `maxAge: 0`, which writes no expiry attribute; renewal skips it. **Every pre-existing cookie is rejected once** — no epoch means no match, deliberately, so no unrevocable cookies survive. Verified 2026-09-02 in two browsers, plus curl devices and hand-forged cookies (see [verification.md](verification.md)): both cookie branches, own sign-out-all, admin cutoff, password change, WS drop («В СЕТИ — 2»→«1»), the refresh-resurrection guard, pre-0012 rejection against a valid-forgery control, and the renewal threshold in both directions. Three defects were found and fixed along the way: sign-out-all navigated to `/login` without clearing client session state so the auth middleware bounced it back; **the rolling window never rolled** — `replaceUserSession` does not reset h3's `session.createdAt`, so every renewal rewrote the same expiry and the design silently degraded to the fixed 400-day-from-first-login window the spec rejected (GOTCHAS #24, since rewritten); and `bumpSignInEpoch`'s `?? 0` fallback could seal a cookie at a fabricated epoch 0                                                             |

| Microphone noise gate (opt-in «Шумовой порог»)                            | ✅ built    | v0.20.0, [ADR 0010](../adr/0010-mic-noise-gate-audioworklet.md). Voice was open-mic from v1 — `ActiveSpeakersChanged` only _displays_ who is talking, so nothing ever gated transmission and every mic was a hot line. A `TrackProcessor` ([mic-gate.ts](../../app/utils/mic-gate.ts)) on the published mic track builds `source → worklet → MediaStreamDestination`; [mic-gate-worklet.js](../../public/mic-gate-worklet.js) does RMS per 128-sample block, `gateHold` hangover, and a per-sample gain ramp (10 ms in / 40 ms out). AudioWorklet, not a rAF loop, because background tabs get timers throttled and the hidden tab _is_ the target case. The 0–100↔RMS curve exists once in [audio-level.ts](../../app/utils/audio-level.ts) — the app converts the threshold and hands raw RMS across, so the worklet holds no copy and the settings marker cannot drift from the gate; the same module replaced the mic test's old linear `rms * 300` scale with dBFS. Never relayed over WS (same reasoning as ADR 0003); prefs (`micMode`/`gateThreshold`/`gateHold`) are per-device localStorage and default to `'open'`. Runs on the Room's `AudioContext` (created unconditionally, contrary to what `webAudioMix: false` suggests — see [gotcha 18i](../GOTCHAS.md)), cached across `init`/`restart` because LiveKit omits it from the restart options. Hardened after an adversarial review that found 14 issues, four of which could make a member silently unheard or silently unfiltered: `toggleMute` republishing an **unprocessed** track after a mic-less join ([gotcha 18k](../GOTCHAS.md)), an unguarded `stopProcessor` leaving the sender on a stopped track, an 8-bit meter whose quantization floor sat under the default threshold, and a memoised `addModule` **rejection** disabling the gate for a whole call. Gates green; verified headed, then a second time across two browsers measuring what the _listener_ receives — gate shut is 91 dB down, mid-call device switch and a backgrounded tab both keep gating, and the mic-less-join → unmute path re-attaches the processor instead of going wide open (see [verification.md](verification.md)) — **still undriven: real speech, Safari/iOS**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
