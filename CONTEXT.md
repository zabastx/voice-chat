# Ubiquitous Language

Glossary for the voice-chat project — a private Discord-style app for one friend group.

- **Space** — the single community this deployment hosts. Implicit; not a stored entity.
- **Channel** — a room the Space hosts; kind is `text`, `voice`, or `dm`. Text and Voice Channels are public to every Member; a `dm` Channel is a private DM Conversation (below) and never appears in the public Channel list or search.
- **Text Channel** — a Channel holding a permanent Message history.
- **Voice Channel** — a Channel members join/leave for live audio, screen share, and shared watching. Persistent (a Discord-style room, not a dial-up call). Maps 1:1 to a LiveKit room.
- **Member** — a registered account. All Members belong to the Space.
- **Role** — a Member's single tier: Admin > Moderator > Member. Strictly hierarchical (each tier holds every power of the tiers below); still no permissions engine.
- **Admin** — the first Member. Holds all Moderator powers plus the destructive and administrative ones: deleting Channels, Members, and other Members' Messages, resetting passwords, and promoting/demoting Moderators. Exactly one.
- **Moderator** — a Member granted organizational powers by the Admin: creating and renaming Channels, and managing Invites. Explicitly _not_ content moderation — no power over Messages or Members. Any number of Moderators; freely revocable by the Admin.
- **Message** — a post by a Member in a Text Channel or a DM Conversation; editable and deletable by its author. The Admin may delete Messages in Text Channels, but has no reach into a DM Conversation they are not a Participant of.
- **Message Source** — the channel through which the author posted a Message: the app UI (`app`) or a messenger bridge (`telegram`, `vk`). Set once at creation; an edit in-app does not change it. Surfaced as a "через Telegram" / "через VK" badge so a bridged reply is distinguishable from a native send.
- **Attachment** — an uploaded file bound to a Message.
- **Direct Message (DM)** — a private, strictly 1:1 conversation between two Members. Reuses the whole Message stack; only its two Participants can read, write, or search it.
- **DM Conversation** — the entity backing a DM: a Channel of kind `dm` with an empty name (its title/avatar are derived from the other Participant). Created on demand, get-or-create, from either Member.
- **Participant** — a Member belonging to a DM Conversation (rows in `channel_participants`). Public Channels have no Participants; access to a DM is gated on Participation.
- **Audience** — the delivery scope of a realtime Message event: every connected client for a public Channel (broadcast), or only the two Participants for a DM Conversation (targeted). Keeps DM traffic off non-participant sockets.
- **Sign-in** — a Member's authenticated presence on one device. Persists across browser restarts when the Member asks to be remembered, and rolls forward as long as they keep using the app; declining to be remembered ends it when the browser closes. Unrelated to a Watch Session — a Sign-in is how a Member gets in, not something they share.
- **Sign-in Epoch** — the generation a Member's Sign-ins belong to. Moving a Member to the next Epoch ends every Sign-in they hold, on every device at once, and affects no other Member. This is the only way to end a Sign-in a Member is not currently holding; it happens when they change their password, when the Admin resets it or cuts them off, and when they ask to be signed out everywhere. A Role change deliberately does not do it.
- **Desktop Client** — the installed Windows form of the app. It presents the same Space and Sign-in as the browser while remaining available from the system tray.
- **Web Release** — the version of the app delivered from the server. It may change without installing a new Desktop Client.
- **Desktop Release** — an installable version of the Desktop Client. It changes the native capabilities or delivery of the app and has a release lifecycle separate from a Web Release.
- **Portable EXE** — a Desktop Client executable that runs without installation while keeping its Sign-in and per-device data in the same Windows profile as the installed client. It is portable as a program file, not as a bundle of user data, and updates by sending the Member to the replacement download.
- **Desktop Update** — a promoted Desktop Release offered to every installed Desktop Client through one shared release stream. It is installed only with the Member's consent and waits until the Member leaves their Voice Channel.
- **Desktop Download** — the promoted Desktop Release offered to a Member who does not have the Desktop Client yet, as an installer with a Portable EXE alternative. Always the same Desktop Release a Desktop Update would offer at that moment — there is no separate download channel. Unlike a Desktop Update, it asks for no consent and waits for nothing: the Member takes it or doesn't. Offered in the browser, before and after Sign-in, and never inside a Desktop Client.
- **Native Bridge** — the narrow contract through which a Web Release can use capabilities supplied by a Desktop Client. A Web Release must tolerate a missing or older Native Bridge.
- **Invite** — a single-use registration token created by the Admin or a Moderator. Redeeming it is the only way to register (except the very first Member, who becomes the Admin).
- **Presence** — whether a Member is currently connected (online/offline). A Member is _offline_ exactly when they have no live WebSocket connection (`wsOnline()`); this is the trigger condition for a Notification.
- **Notification Transport** — a messenger that can carry a Notification to an offline Member: Telegram or VK. Each is independently configured and independently linkable; a Member may use either, both, or neither.
- **Messenger Link** — the opt-in binding between a Member and one account on a Notification Transport, established via a Linking Token. The external id (a Telegram chat, a VK peer) is a secret that never appears in a Member DTO or the session cookie; a Member sees only their own status via `GET /api/me/notifications/<transport>`. A VK peer id is also the Member's public VK user id, so leaking one deanonymises them.
- **Linking Token** — a short-lived (15 min), single-use secret embedded in a deep link: `t.me/<bot>?start=<token>` for Telegram, `vk.me/club<id>?ref=<token>` for VK. Consumed on the Member's first tap («Start» / «Начать»), binding that messenger account to the Member.
- **Notification** — a message a Notification Transport delivers to an offline, linked Member when they are `@`-mentioned in a Text Channel or receive any DM. Contains the sender, place, full text (URLs preserved as bare clickable links, markdown stripped), and and any Attachments, each forwarded by whatever the Transport offers: Telegram maps them onto `sendVoice`/`sendPhoto`/`sendVideo`/`sendDocument`, while VK carries text and attachments in one send and routes everything but images through its document path — so a voice message arrives playable but not as an inline waveform.
- **Notification Mapping** — a stored row `{transport, external_chat_id, external_message_id, conversation_message_id, member_id, channel_id}` recorded for each delivered Notification, so a reply in the messenger routes back to the exact Channel/DM as the right Member. VK has two message id spaces and a reply may reference either, hence both columns. Swept after 7 days.
- **Reply-to-send** — replying to a Notification in the messenger posts the reply back into the app: resolved through the Notification Mapping, run through the normal Message send path (mentions encoded, same Audience), authored as the linked Member.
- **Voice State** — which Voice Channel a Member is currently in, plus mute/speaking status; visible to all Members without joining.
- **Self-Mute** — a Member muting their own microphone. Broadcast to everyone via Voice State; the whole room stops hearing that Member.
- **Mic Mode** — a per-device rule for how captured microphone audio is transmitted: continuously (`open`) or only while the noise gate is open (`gate`). Push-to-talk is a possible future mode, outside the current Desktop Release plan.
- **Local Volume** — a listener's per-speaker playback level (0–200%, default 100%), applied only in the listener's own browser. Purely client-side: it never touches the speaker's mic or any other listener. Persisted per-device (localStorage), keyed by the speaker's Member id.
- **Local Mute** — a listener silencing one specific speaker for themselves only (Local Volume forced to 0 via a separate flag that preserves the prior level). Distinct from Self-Mute (which is the speaker's own choice, seen by all) and from any server/admin force-mute (which this app does not have).
- **Capture Device** — which microphone or camera this browser records from. Per-device and client-side (localStorage), like Screen Share Settings: device ids are per-machine and never reach the server. Affects what every other Member hears and sees — unlike Local Volume, which only ever changes what one listener hears — but says nothing about _how_ the signal is transmitted, which is Mic Mode. Falls back to the system default when unset or when the chosen device disappears; a Member is never silenced by a Capture Device going away.
- **Playback Device** — which speaker or headset this browser plays a Voice Channel through. Per-device and client-side only, like Local Volume and Watch Volume: no other Member is affected by the choice or can observe it — the mirror image of a Capture Device, and unrelated to Mic Mode, which shapes what this Member sends rather than what they hear. Stored in the same localStorage as Screen Share Settings. Browsers without output-device selection offer only the system default. Covers the Members' voices and nothing else — a Watch Session plays inside an external site's frame this app cannot redirect, so choosing headphones moves the voices there and leaves the video on the system default.
- **Screen Share Settings** — a Member's per-device choice of screen-share quality preset (`h1080fps15`, `h1080fps30`, or `original`), captured in a pre-share dialog at share start and persisted as the next-share default. Works Discord-style: settings apply when the share begins, not on the fly — changing requires stop and re-share. Not a server-side Member property: browser capture capabilities differ per machine, so it lives in the same localStorage as microphone/camera device ids. Distinct from Voice State (which tracks _who_ is sharing, not _how_).
- **Watch Session** — a shared viewing of an external video (a YouTube video or a Twitch live stream) held inside a Voice Channel. At most one per Voice Channel; starting another replaces it. Carries only _what_ to play and _where in it_ everyone is — each Member's own device fetches the video, so picture quality, subtitles and ads are each Member's own. Distinct from Screen Share, which relays one Member's picture to everyone: a Screen Share can show anything, a Watch Session only what an external site will hand to each Member directly. Visible to every Member from the Channel list, not only to those watching — a Watch Session is an invitation.
- **Watch Audience** — who is watching a Watch Session: exactly the Voice Channel's roster. Not a separate membership — joining the Voice Channel is joining the watch, leaving it is leaving the watch. Every Member of the Audience may play, pause, seek and replace; there is no host and no owner. An empty Audience pauses a Watch Session rather than ending it.
- **Live Broadcast** — a Watch Session whose source is streaming now rather than recorded. It has no shared timeline: every Member rides the live edge, so only pausing is shared and position is meaningless. Not a separate kind of Watch Session — the same session becomes one the moment a Member's player reports the source is live.
- **Playback Anchor** — the shared answer to "what is playing, and where": whether it is paused, and the position it stood at. A fixed point, not a running clock — each device counts forward from it on its own. A Live Broadcast has no Playback Anchor worth the name; only its paused state is shared.
- **Drift** — the gap between one Member's actual playback position and the Playback Anchor, opened by buffering or by an ad only that Member is shown. Corrected by the drifting Member alone: no Member's playback ever waits on another's. Undefined for a Live Broadcast, which has no position to drift from.
- **Watch Volume** — a Member's per-device playback level for a Watch Session's audio. Distinct from Local Volume, which sets how loud _another Member_ sounds; a Watch Session is nobody's voice, so the two are separate settings and never share a value.
